# Коли контролери кращі за minimal API

Minimal API виграє на швидкості й AOT. Але в кількох випадках контролери — точно правильний вибір.

**1. Конвенції з коробки.** Атрибут `[ApiController]` дає безкоштовно:
- **автоматична валідація** — модель перевіряється за атрибутами (`[Required]`, `[Range]`…), і при помилці сам повертається 400 з деталями, без коду в ендпоінті;
- **inference джерела біндингу** — фреймворк сам вгадує, звідки брати параметр (тіло, маршрут, query), не треба ручних `[FromBody]`/`[FromRoute]`.

У minimal API це доробляєш руками.

**2. ORM.** EF Core тримається на рефлексії, і вона йому необхідна — це рідна стихія контролерів, не minimal API.

**3. Endpoint filters слабші на масштабі.** Це механізм крос-катінгу minimal API. Мінус: вішаються **імперативно** (руками на кожен ендпоінт), тоді як контролерні фільтри — **декларативно за областю** (глобально / контролер / екшн). На багатьох ендпоінтах декларативність виграє.

**4. Масштаб.** Для великого API контролери структурованіші й тримають команду в єдиному стилі.

**Підсумок:** контролери кращі, коли треба зрілі конвенції, EF Core і структура на масштабі.
