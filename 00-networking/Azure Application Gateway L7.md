# Azure Application Gateway (L7)

**Регіональний L7-реверс-проксі, що читає HTTP** (URL, host-заголовок, кукі) і на основі вмісту ухвалює розумні рішення. Живе **всередині твоєї VNet** і може фронтити приватні бекенди. Це **проксі** — термінує з'єднання, розпаковує, і відкриває власне до бекенда.

## Що вміє (бо читає HTTP)
- **Path-based routing** — `/api/*` → один пул, `/images/*` → інший;
- **Host-based / multi-site** — кілька доменів на одному шлюзі → різні бекенди;
- **TLS-термінація (SSL offload)** — серти з Key Vault;
- **Cookie-based session affinity** — липкі сесії по кукі (точно по браузеру, не по IP);
- **WAF** — фаєрвол проти OWASP-атак (SKU WAF_v2);
- **URL/header rewrite, редиректи** (HTTP→HTTPS), **connection draining**;
- **Розумні health-проби** — перевіряють справжній `/health` (статус+вміст), а не лише відкритий порт;
- **Автоскейлінг** (v2).

## Практичний толк
- **Один публічний вхід** (один IP/серт/WAF) перед **багатьма бекенд-сервісами**, розведеними за шляхом/хостом → мікросервіси за однією адресою, а внутрішню кухню міняєш вільно, нічого клієнту не ламаючи;
- **SPA + API на одному домені** → той самий origin → **CORS зникає**;
- **Zero-downtime деплой** — connection draining дає поточним запитам догратися під час розкатки;
- **Централізація крос-катінгу** — TLS, WAF, редиректи, безпекові заголовки в одному місці, а не в кожному сервісі.

## З чого складається
Frontend IP (публічний/приватний) → **listeners** (порт/протокол/хост) → **rules** (+ path map) → **backend pools** (VM/VMSS/App Service/AKS/IP) → HTTP settings, health probes, WAF policy.

## SKU
**v2** (Standard_v2, WAF_v2) — автоскейл, zone-redundant. v1 — легасі, виводиться.

## .NET-момент
Термінує TLS → апка бачить **HTTP + `X-Forwarded-*`** → потрібен **`ForwardedHeaders`**, щоб знала реальну схему й IP клієнта.

## Межа / де НЕ треба
- **Не-HTTP** трафік → це Load Balancer (L4), App Gateway його не тягне;
- **Глобальний мульти-регіон** → він регіональний;
- **Проста одна апка на App Service** → вбудованого ingress вистачає, окремий шлюз = зайва базова вартість + складність;
- **WAF false positives** — керовані правила можуть різати легітимний трафік, треба тюнити винятки.

**Суть:** Application Gateway — регіональний **L7-проксі, що читає HTTP** і тому вміє path/host-роутинг, TLS-offload, WAF і cookie-affinity. Реальний толк — **один вхід перед багатьма сервісами + централізація крос-катінгу + zero-downtime**. Живе у VNet (може фронтити приватні бекенди). Не для не-HTTP, не для глобального масштабу, і оверкіл для однієї простої апки.
