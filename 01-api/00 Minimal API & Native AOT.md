# Minimal API + Native AOT

**Що це:** minimal API — легка модель ендпоінтів без контролерів; Native AOT — компіляція в нативний бінар на етапі збірки, без JIT.

**Чим крута (суть за хвилину):**
- **Майже миттєвий старт** (десятки мс замість сотень) + **крихітний образ** (десятки МБ замість сотень) — бо немає JIT-прогріву й рантайму в комплекті.
- Це **вбиває cold start** → .NET нарешті годиться під **serverless / scale-to-zero** (Azure Container Apps: у простої платиш нуль, автоскейл реагує миттєво).
- По суті **Go-подібні характеристики деплою при продуктивності C#** — .NET заходить у нішу, де раніше сиділи тільки Go/Rust.
- Пара **невипадкова**: контролери під AOT не годяться (забагато рефлексії), тому саме minimal API — офіційний AOT-шлях.

**Щоб не звучати наївно (де не треба):** для **always-on** сервісу вигода зникає, а рефлексіє-важкий стек (EF Core, AutoMapper) під AOT ламається. Тобто це **прицільно під старт/розмір/scale-to-zero**, а не дефолт на все.
