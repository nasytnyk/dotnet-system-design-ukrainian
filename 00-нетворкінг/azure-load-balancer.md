# Azure Load Balancer (L4)

Регіональний балансувальник **рівня 4 (TCP/UDP)**, що розкидає з'єднання по пулу бекендів. **Сліпий до HTTP** — не читає URL, не термінує TLS. «Тупий, але блискавичний».

## Що значить «L4 pass-through»
- **L4** — бачить лише **IP + порт + протокол**, не заглядає в HTTP.
- **Pass-through (не проксі)** — не термінує з'єднання й не відкриває своє до бекенда, лише **направляє пакети**; бекенд бачить фактично оригінальне з'єднання. Тому **дуже швидкий**, але **не вміє** TLS-термінацію, HTTP-роутинг, WAF, кеш.

## Як розкидає: 5-tuple hash
- хешує **(source IP, source port, dest IP, dest port, protocol)** → обирає бекенд;
- усі пакети **одного** з'єднання → той самий бекенд; **нове** з'єднання (новий випадковий порт) → інший → рівний розподіл **без підрахунку навантаження**;
- **session persistence (affinity)** — хеш по меншому набору (source+dest IP): **той самий клієнт завжди на той самий бекенд**. Треба, коли бекенд тримає стан сесії; але краще робити бекенди **stateless** і не залежати від цього.

## Failover — швидкий, регіональний
Health-проби (TCP/HTTP/HTTPS) стукають у бекенди; нездоровий **викидається з ротації**. Швидко (за інтервалом проби, не за DNS-кешами) — але **в межах одного регіону**.

## Public / Internal
- **Public** — публічний IP, інтернет→VM, заодно дає **вихідний доступ (SNAT)**;
- **Internal** — приватний IP, балансування **ярус→ярус** усередині VNet.

## Для чого й на що
- **Не-HTTP протоколи** (бази, ігрові сервери, SMTP, свій TCP/UDP) — там L4 ідеальний;
- внутрішнє ярус-до-ярусу; макс швидкість/низька латентність.
- **Цілі:** VM / VMSS; під капотом ним користується **AKS**. На **App Service / Container Apps** сам LB не піднімаєш — у них балансування вбудоване.

## SNAT port exhaustion (продакшн-пастка)
Коли VM за **публічним** LB роблять багато **вихідних** з'єднань, вони ділять **обмежений пул SNAT-портів** (SNAT = багато приватних VM виходять в інтернет через один публічний IP). Забагато одночасних → **порти вичерпуються** → нові з'єднання падають.
**Фікс:** **NAT Gateway** (рекомендований шлях для вихідного), більше frontend-IP, **перевикористання з'єднань** (тримати `HttpClient`, а не відкривати нове щоразу).

## Межа / де НЕ треба
- HTTP з **path-роутингом / WAF / TLS-offload** → це **Application Gateway (L7)**, не LB;
- **глобальний мульти-регіон** → не його рівень (він регіональний);
- **Basic SKU** виводиться з експлуатації (~вересень 2025) → бери **Standard**.

**Суть:** Azure Load Balancer — регіональний **L4 pass-through** роздавач: хешує потоки на бекенди (5-tuple), шалено швидкий, будь-який TCP/UDP, зі швидким health-probe failover — але **сліпий до HTTP** і **тільки регіональний**. Головна експлуатаційна пастка — **SNAT port exhaustion**, що фіксять NAT Gateway'єм і перевикористанням з'єднань.
