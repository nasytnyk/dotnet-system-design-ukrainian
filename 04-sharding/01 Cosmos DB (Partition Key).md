# Cosmos DB — шардинг

## Як шардить
- Обираєш **partition key** (напр. `userId`); Cosmos **хешує** його й розкидає документи по **фізичних партиціях** (машинах), тримаючи однаковий ключ разом.
- **Повністю автоматично:** Cosmos сам **додає партиції й перебалансовує** з ростом даних/навантаження. Шарди ти **не бачиш і не адмініструєш**.

## Виграш
Горизонтальний масштаб + еластичність **без ручного розміщення шардів**; читання за одиниці мілісекунд при попаданні в один ключ.

## Межа (головне)
**Вибір ключа — на тобі.** Гарячі запити мають бути **однопартиційними** (дешево); поганий ключ → **гаряча партиція** або **крос-партиційний fan-out** (дорого по RU).

**Суть (пара речень для співбесіди):** Cosmos шардить автоматично по **хешу partition key** — сам додає й балансує партиції, ти шардами не керуєш. Уся майстерність — **обрати ключ під патерн доступу**, щоб гарячі запити лишались однопартиційними, бо крос-партиційний **fan-out дорогий по RU**.
