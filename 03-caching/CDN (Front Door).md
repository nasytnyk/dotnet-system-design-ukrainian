# Azure CDN (edge caching)

## Що це
**CDN** = кеш статики на **edge-серверах (POP)** близько до юзера. Виграш: **швидше + розвантаження origin + дешевший egress**. Найзовнішній рівень кешу (HTTP-контент на краю мережі).

## Azure = Front Door
Класичні окремі Azure CDN виводяться → сьогодні CDN це **Azure Front Door** (CDN + L7-роутинг + WAF в одному).

## Як ефективно закешувати статику (головне)
1. **`Cache-Control` на статику** — `public, max-age=31536000, immutable` (у коді через `UseStaticFiles` → `OnPrepareResponse`). Front Door його **поважає за замовчуванням**.
2. **Версіоновані імена файлів** (`app.a1b2c3.js`) → кешуй вічно **без stale**: змінив файл → нове ім'я → новий кеш.
3. **Route з `cacheConfiguration`** + **`IgnoreQueryString`** (щоб `?v=1` не плодив копій) + компресія on.
4. Перевірка: **access log → cache status `HIT` / `MISS`**.

## Великі файли / відео
- **Великі блоби** тягне той самий Front Door через **byte-range (чанкове) кешування** (резюмовані завантаження) — окремий CDN **не потрібен**.
- **Відео:** Azure Media Services **закрито (2024)** → Front Door CDN + **зовнішній енкодер** (HLS/DASH-сегменти).

## Межа / де НЕ треба
- **Динамічний per-user контент** — кешувати нема чого;
- **приватний/автентифікований** — обережно (кеш спільний), тільки через **SAS / signed URLs**;
- **stale після деплою** → версіонуй імена або **purge**;
- **малий обсяг, один регіон** → прямий origin, CDN оверкіл.

**Суть:** CDN = кеш статики на краю (швидкість + розвантаження + дешевший egress). В Azure це **Front Door**. Ефективність дають **`Cache-Control` + версіоновані імена**, а на route — **кеш + `IgnoreQueryString`**. Великі файли — той самий Front Door (byte-range); відео — Front Door + зовнішній енкодер (AMS закрито). Не для per-user динаміки й приватного без signed URLs.
