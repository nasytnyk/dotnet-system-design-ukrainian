# CAP через Cosmos DB

## CAP коротко
Розподілена система з копіями даних на кількох вузлах. Коли **мережа між вузлами рветься (розрив)** — доводиться обирати:
- **C (Consistency)** — читання бачить **найсвіжіше**; вузол краще **відмовить**, ніж віддасть старе;
- **A (Availability)** — вузол **завжди відповідає**, але, можливо, застарілим.
- **P (Partition tolerance)** — **обов'язковий** (мережа рветься завжди), тож реальний вибір — **C чи A під час розриву**. Без розриву маєш обидва.

## Cosmos DB = слайдер C↔A
Cosmos не замикає в одному куті — дає **5 рівнів консистентності**, і ти сам крутиш повзунок:
- **Strong** — усі бачать однакове найсвіжіше (найближче до **C**); дорожче й повільніше;
- **Bounded staleness** — узгоджено з обмеженим відставанням;
- **Session** — узгоджено **в межах твоєї сесії** (читаєш свої ж записи); **дефолт**, добрий баланс;
- **Consistent prefix** — не бачиш записи «не по порядку»;
- **Eventual** — найдоступніше й найшвидше (найближче до **A**), але можеш бачити старе.

## Головне
- Обираєш рівень **під сценарій:** гроші/критичне → ближче до **Strong**; лайки/стрічка/кошик → **Eventual**.
- **Сильніша консистентність = вища латентність навіть без розриву** — за узгодженість платиш очікуванням, поки репліки погодяться.

**Суть (пара речень для співбесіди):** CAP каже, що при **розриві мережі** обираєш **C (краще відмовити) чи A (краще застаріле)**, бо P обов'язковий. Cosmos DB робить це наочним — **5 рівнів консистентності** від **Strong** (C) до **Eventual** (A), і ти крутиш повзунок під сценарій. Плюс: сильніша консистентність коштує **латентності** навіть без розриву.
