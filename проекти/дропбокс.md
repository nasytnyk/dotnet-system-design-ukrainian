# Dropbox: .NET/Azure специфіка

## Файли → Azure Blob Storage (block blobs)
Основа всього. **Block blobs** створені саме під великі файли (до ~190 TiB, до 50 000 блоків), плюс access tiers (Hot/Cool/Archive) для здешевлення. Версіонування і антивірус — нативні (**Blob versioning** + **Defender for Storage**), руками не пишемо.

## Метадані → Cosmos DB
Доступ до метаданих — це lookup по ключу (`fileId`), гнучка схема, горизонтальний масштаб під купу дрібних записів. **Перевага Cosmos DB:** партиціонування «з коробки», читання за одиниці мілісекунд, гнучка схема і нативний **TTL** — те, що ідеально лягає під цей патерн.

## Авторизація → одним рядком
ASP.NET Core JWT Bearer middleware сам валідує токен (підпис/issuer/expiry), токени видає **Microsoft Entra ID** — свого коду нуль, лише конфіг + `[Authorize]`.

## Прямий аплоад → SAS
Правильний підхід: клієнт ллє **напряму в Blob Storage**, минаючи бекенд. Механізм — **SAS (Shared Access Signature)**: короткоживучий URL із вшитим дозволом рівно на цей блоб.

- **Звідки сигнатура:** бекенд підписує параметри (який блоб, які права, доки діє) і додає підпис у сам URL. Blob Storage перевіряє підпис — валідний, значить дозвіл справжній. Бекенд лише видає перепустку, а трафік іде повз нього.
- **User Delegation SAS:** підпис не майстер-ключем стораджу, а обліковкою **Entra ID**. Безпечніше — не світиш головний ключ, і токен можна відкликати.

## Чанки → SDK робить сам
Block blob збирається з блоків (**Put Block / Put Block List**): resume при обриві, паралельність, перевірка цілісності кожного блоку. Руками не пишемо: у браузері чанкає **JS SDK** (`@azure/storage-blob`), у десктопі — **.NET SDK** (`BlobClient.UploadAsync` зі `StorageTransferOptions`).

## Великі файли → десктоп-агент
Для файлів на десятки ГБ — **нативний sync-агент, а не браузер** (браузер має ліміти пам'яті й крихкий на таких обсягах). Агент на .NET **кросплатформний** — одна кодова база під Win/Mac/Linux (`FileSystemWatcher` під капотом лягає на inotify/FSEvents).

## Шаринг по лінку → Cosmos DB
Окремий патерн: lookup по `shareId`, read-heavy (публічний лінк смикають анонімно), протермінування. **Cosmos DB** ідеальний — key-lookup + нативний **TTL**, який сам чистить протерміновані лінки без жодної cron-джоби.

## Безпека → мінімум, усе з коробки
- **In transit:** TLS + SAS тільки по HTTPS.
- **At rest:** Azure Storage шифрує **за замовчуванням** (AES-256).
- **Доступ:** короткоживучі SAS + Private Endpoints, щоб блоб не стирчав у публічний інтернет.
