# SOAP в Azure (легасі за фасадом)

**SOAP** — старий важкий XML-протокол веб-сервісів (конверти + WSDL-контракт + WS-*). **Нове на ньому не пишуть** — зустрічаєш лише в старих enterprise/B2B/банк/держ системах.

## Як адаптувати в Azure (головне)
**APIM імпортує WSDL** і виставляє SOAP через шлюз двома способами:
- **SOAP pass-through** — просто прикриває старий сервіс;
- **SOAP-to-REST** — перетворює легасі-SOAP на сучасний **REST/JSON на краю, без переписування бекенда**. Нові клієнти бачать нормальний REST-фасад, а динозавр лишається як є.

## .NET (одним рядком)
Споживати SOAP легко (клієнт із WSDL); хостити на сучасному .NET — тільки через **CoreWCF** і лише для міграції легасі.

**Суть:** не будуй нове на SOAP. Успадкував старий → **APIM обгортає його в REST (SOAP-to-REST)**, система живе в сучасності, поки динозавр дотягує вік за фасадом.
