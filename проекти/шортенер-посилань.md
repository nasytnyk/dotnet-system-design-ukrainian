# Шортенер посилань: .NET/Azure специфіка

## Скелет — просто щоб був
Сутності (довгий URL, короткий код) і API (`POST` створити, `GET` редіректнути) малюються одним рядком і проговорюються швидко. Це обов'язкова база, але **не там оцінюють** — весь сигнал у deep dives нижче.

## Генерація короткого коду: Sqids
**Sqids** (раніше — **Hashids**, створений Іваном Акімовим ще ~2012, у 2023 переосмислений і перейменований у Sqids) — це бібліотека, яка **оборотно** кодує ціле число в короткий URL-безпечний рядок і назад. Це не хеш і не шифрування, а обфускація: бере послідовний `id` з лічильника й перетворює його на несеквенційний код.

**Навіщо тут:** лічильник дає гарантовану унікальність (немає колізій), але його коди йдуть підряд → базу можна спарсити перебором. Sqids ховає цю послідовність, зберігаючи унікальність. Тобто береш найкраще від лічильника + непередбачуваність хешу. У .NET доступний як `Sqids.NET` (і легасі-порт `Hashids.net`).

## Атомарний лічильник: варіанти на Azure

**Azure Cache for Redis** — керований Redis, дефолтний вибір. `INCR`/`INCRBY` атомарні, однопоточний рушій виключає гонки. Для масштабу — видавати не по одному ID, а діапазонами (`INCRBY 1000`) і роздавати їх локально.

**Azure SQL — об'єкт `SEQUENCE`.** Особливість: це **самостійний об'єкт-лічильник на рівні схеми, не прив'язаний до колонки таблиці** (на відміну від `IDENTITY`) — його можна шарити між таблицями. З опцією `CACHE 1000` віддає діапазони з пам'яті й дуже швидкий. Важливий нюанс: при аварійному падінні може *пропустити* діапазон (діра), але **ніколи не видає значення двічі** — а нам саме це й треба (дірки безпечні, повтори — ні). Durable за природою.

**Cosmos DB** — має атомарний `Increment` через Patch-операцію. **Недолік:** один лічильник = один документ = **гаряча партиція**: усі записи б'ють в одну логічну партицію → throttling, не масштабується. Згадувати радше як приклад «чому так не роблять».

## Редірект: 302 проти 301
Момент не дотнетний, але сильний. **301 (permanent)** браузери й проксі кешують намертво → **втрачаєш аналітику кліків** і не можеш змінити/протермінувати ціль. **302 (temporary)** → кожен клік проходить через твій сервер → зберігаєш контроль і статистику. Тому для шортенера — 302.

## Edge/масштаб читань: Azure Front Door
Читань набагато більше за записи, тому редірект хочеться віддавати якнайближче до користувача. **Azure Front Door** — глобальна L7-точка входу з rules engine: може **робити редіректи й кешувати гарячі коди на краю**, не доходячи до origin (роль, аналогічна Cloudflare Workers / Lambda@Edge), плюс маршрутизація між регіонами та розведення read/write бекендів. Це найближчий Azure-аналог edge-редіректу, хоч і слабший за Cloudflare Workers.
