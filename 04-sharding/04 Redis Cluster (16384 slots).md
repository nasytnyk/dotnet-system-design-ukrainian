# Redis Cluster — шардинг

## Що це
Коли кеш переростає **одну ноду** (за пам'яттю чи пропускною), Redis шардять — кластеризація в **Azure Cache for Redis Premium** / **Azure Managed Redis**. Той самий принцип шардингу, але для **кеш-шару**.

## Як шардить
- Простір ключів ділиться на **16384 hash-slots**;
- кожен ключ хешується (**CRC16(ключ) mod 16384**) → потрапляє в слот, а слоти розкидані по **шардах (нодах)**;
- Azure керує кластером: обираєш кількість шардів, він розподіляє слоти й **ребалансує/ресайзить**;
- **клієнт cluster-aware** (StackExchange.Redis) знає, який слот на якій ноді, і **шле команду прямо туди**.

## Виграш
Горизонтальний масштаб кешу — **більше RAM і більше ops/sec** просто додаванням шардів.

## Межа (головне)
- **Мульти-ключові операції** (MGET, транзакції, Lua) вимагають, щоб усі ключі були **в одному слоті** — інакше не спрацюють через слоти;
- рятують **hash tags:** `user:{42}:profile` і `user:{42}:cart` → однаковий `{42}` кладе їх у **той самий слот** (co-location);
- **гарячий ключ** → гарячий шард.

**Суть (пара речень для співбесіди):** Redis Cluster ділить простір ключів на **16384 hash-slots**, розкидані по шардах; кожен ключ хешується в слот, тож ключі авто-розподіляються по нодах → більше пам'яті й throughput. Клієнт cluster-aware маршрутизує сам. Каверза — **мульти-ключові операції мають потрапити в один слот**, що вирішують **hash tags `{}`** для co-location зв'язаних ключів.
