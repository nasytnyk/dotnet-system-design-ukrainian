# Сирий WebSockets проти SignalR (.NET/Azure)

WebSocket — **повнодуплексний персистентний** канал: починається як HTTP-запит з `Upgrade`, сервер відповідає **`101 Switching Protocols`**, і далі з'єднання **перестає бути HTTP**. Питання не «чи брати WebSocket», а **на якому рівні абстракції** з ним працювати.

## Сирий WebSockets
`app.UseWebSockets()` + `AcceptWebSocketAsync()` в ASP.NET Core. Ти **сам** керуєш кадрами, серіалізацією, реконектом, розсилкою по клієнтах.
- **Плюс:** повний контроль, мінімум оверхеду, **свій протокол**.
- **Мінус:** усе руками — реконект, групи, адресація, жодного фолбеку.

## SignalR
Абстракція зверху. Не проста обгортка: **негоціює транспорт** (WebSocket пріоритетно, нижче — фолбек), **авто-реконект**, RPC-**хаби**, **групи**, адресація по `userId`.
- **Плюс:** купа готового, у рази менше коду.
- **Мінус:** **SignalR-протокол** — обидва кінці мають бути SignalR-сумісні; тонкий шар оверхеду абстракції.

## На масштабі — два керовані дзеркала цього ж вибору
Обидва **знімають персистентні конекшни з твоїх серверів** (апка stateless, без ручного backplane):

- **Azure Web PubSub** = «**сирий WebSocket** на масштабі». Протокол-агностичний, будь-яка мова, сирий ws, субпротоколи. Дзеркало сирого підходу.
- **Azure SignalR Service** = «**SignalR** на масштабі». .NET-хаби, групи, адресація; режими default і **serverless** (з Functions). Дзеркало SignalR.

## Що обирати
- **SignalR (+ SignalR Service)** — дефолт для .NET: чат, presence, нотифікації, дашборди. Коли хочеш готові групи/реконект/адресацію і не мучитися.
- **Сирий WebSockets (+ Web PubSub)** — коли треба **свій протокол**, мінімальний оверхед, клієнти **не .NET**, або повний контроль над кадрами.

## Межа / де оверкіл
- **Сирий ws «бо контроль»** на звичайному .NET-реалтаймі — ти перевинаходиш реконект/групи/фолбек, які SignalR дає безкоштовно.
- **SignalR**, коли клієнти поліглотні й хаби не потрібні — тоді сирий ws / Web PubSub чистіші.
- Персистентні конекшни **stateful** у будь-якому разі → на масштабі бери **керований сервіс**, не тримай конекшни на апп-серверах.
