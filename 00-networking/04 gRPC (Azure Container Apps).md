## Мінімум для gRPC між мікросервісами на Azure

**1. .NET-частина (сам gRPC):**
- `.proto` — контракт;
- **`Grpc.Tools`** генерує C# на білді;
- сервер на **`Grpc.AspNetCore`**, клієнт — типізований поверх `GrpcChannel`.

**2. Хост — Azure Container Apps:**
- деплоїш сервіси туди;
- вмикаєш **внутрішній ingress** (вхідні ворота середовища) з **`transport: http2`**;
- сервіси кличуть одне одного за внутрішнім DNS-іменем.

**3. Чому саме Container Apps — і є весь секрет:**
gRPC іде поверх HTTP/2, який **пхає всі виклики в один довгий конекшн**. Простий L4-балансер «прилипає» ним до одного інстансу → решта стоять голодні. Але інгрес Container Apps на **Envoy** (L7-проксі, що розуміє HTTP/2) розкидає **по викликах** — тобто **пастка балансування вирішена за тебе з коробки**. Ти нічого окремо не налаштовуєш.

**Що свідомо НЕ входить у мінімум** (це вже продакшн-загартовування, не «підняти»):
- Dapr / service mesh / mTLS — шифрування й мережеві плюшки;
- Managed Identity — авторизація сервісів;
- APIM — тільки якщо треба публічний вхід;
- keepalive-тюнінг, observability.

**Суть:** `.proto` + `Grpc.Tools` + `Grpc.AspNetCore` → задеплой у **Container Apps з ingress http2** → його Envoy сам вирішує проблему балансування HTTP/2. Це і є весь мінімум.
