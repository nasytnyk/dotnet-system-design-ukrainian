# Azure Front Door

**Глобальний L7-реверс-проксі на краю мережі Microsoft** (anycast, понад сотня точок присутності) — єдиний глобальний вхід твого застосунку. Злив у собі кілька колись окремих речей: **глобальну маршрутизацію + CDN + WAF + TLS + DDoS-захист**. Суть — робить апку **швидкою, доступною й безпечною по всьому світу з однієї точки**.

## Швидко
- **Anycast + найближчий edge** — один IP, юзер конектиться до найближчої точки, короткий перший стрибок.
- **TLS термінується біля юзера** — дорогий хендшейк поруч, а не через океан.
- **Приватний бекбон Microsoft** — від краю до origin трафік іде власною магістраллю, не публічним інтернетом (менше стрибків, стабільніша латентність).
- **CDN-кеш на краю** — статика (картинки/CSS/JS) віддається з edge, не турбуючи origin.
- **HTTP/2 і HTTP/3** до клієнтів.

## Доступно
- **Health-проби** + **швидкий failover** (Front Door у потоці трафіку, тому реагує одразу, а не через DNS-кеші).
- **Методи маршрутизації:** latency (найближчий живий), priority (active-passive), weighted (канарка/поступова розкатка).
- **Origin groups** — набір бекендів по регіонах із failover між ними (мульти-регіон active-active / active-passive).

## Безпечно
- **WAF на краю** — OWASP-правила, бот-захист, rate limiting, гео-фільтр.
- **DDoS** гаситься масштабом краю.
- **TLS** — керовані серти, мінімальна версія.
- **Private Link до origin (Premium)** — бекенд дістається приватно й **взагалі не стирчить у публічний інтернет**.

## L7-розумність
Path/host-роутинг, URL rewrite/redirect, маніпуляція заголовками, правила кешу, rule engine — ті самі L7-фічі, але на глобальному краю.

## Тіри
- **Standard** — CDN + статика + маршрутизація + базовий WAF;
- **Premium** — керовані WAF-правила (бот-захист, набори правил) + **Private Link до origin**.

## .NET-момент
TLS термінується на Front Door → апка бачить **HTTP + `X-Forwarded-*`** → потрібен **`ForwardedHeaders`**. Origin — App Service, Container Apps, AKS, Storage (статичний сайт) або приватний через Private Link. Класика: **статичний SPA кешується на краю + API роутиться на бекенд**.

## Межа / де НЕ треба
- **Суто внутрішні апки** (не в інтернет) → Front Door це публічний край;
- **один регіон, локальні юзери, без CDN/WAF** → часто вистачає самого App Service;
- **не-HTTP** → тільки HTTP(S);
- **крихітний проєкт/дев** → базова ціна + складність, оверкіл.

**Суть:** Front Door — це **глобальний край застосунку**: anycast-вхід, що термінує TLS біля юзера, веде трафік приватним бекбоном Microsoft, кешує статику (CDN), захищає WAF+DDoS і робить швидкий failover між регіонами. Швидко / доступно / безпечно — з однієї точки, для всього світу.
